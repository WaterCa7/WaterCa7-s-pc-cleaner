# Автообновление Windows-версии и открытие репозитория

Дата: 2026-10-17. Статус: одобрено пользователем, ждёт плана реализации.

## Цель

У человека всегда последняя версия программы: она сама находит новую версию, скачивает, проверяет и ставит её.
Первым выходит релиз **1.1.0** для Windows: новая иконка и автообновление. Mac-версия (Avalonia) идёт отдельным
проектом со своей спецификацией и потом подключается к той же схеме обновлений.

Не входит: обновление версии 1.0.0 (она не умеет проверять обновления, её пользователи один раз скачают 1.1.0 вручную),
периодическая проверка во время работы, каналы beta/stable, дельта-обновления.

## Решения пользователя

- Релизы публикуются в этом репозитории, репозиторий становится **публичным**, лицензия **MIT**.
- Адрес `<old-address>` в истории коммитов заменяется на `149539786+WaterCa7@users.noreply.github.com`
  до открытия репозитория.
- Обновление **автоматическое**, без вопроса; в «Настройках» его можно выключить.
- Порядок: сначала автообновление для Windows и релиз 1.1.0, потом Mac.

## Файлы релиза

В каждом релизе `vX.Y.Z`:

| Файл | Что это |
|---|---|
| `WaterCa7sPcCleaner.exe` | single-file сборка из CI |
| `update.json` | описание обновления (UTF-8) |
| `update.json.sig` | подпись ECDSA P-256 / SHA-256 байтов `update.json`, формат DER (как у `openssl dgst -sign`) |

```json
{
  "version": "1.1.0",
  "published": "2026-10-20T12:00:00Z",
  "notes": "Что нового — текст на русском",
  "files": {
    "win-x64": {
      "name": "WaterCa7sPcCleaner.exe",
      "url": "https://github.com/WaterCa7/WaterCa7-s-pc-cleaner/releases/download/v1.1.0/WaterCa7sPcCleaner.exe",
      "size": 67037265,
      "sha256": "4dedd…"
    }
  }
}
```

Mac-версия позже добавит ключи `osx-arm64` / `osx-x64`; Windows-версия смотрит только на `win-x64`.

## Ключ подписи

- Пара ключей ECDSA P-256 создаётся один раз. Закрытый ключ хранится в секрете GitHub Actions `UPDATE_SIGNING_KEY`
  и в резервной копии у владельца (вне репозитория); в репозитории его нет.
- Открытый ключ лежит в `tools/update-signing-public.pem` и вшит в программу (`Core/Updates/UpdateKeys.cs`);
  тест проверяет, что они совпадают.
- Потеря закрытого ключа = старые версии не примут новые релизы, людям придётся один раз скачать вручную.

## Как работает программа

Код — в `src/PcCleaner/Core/Updates/`, каждая часть отдельно тестируется:

- `UpdateManifest` — разбор `update.json` и проверки: версия выше текущей, есть `win-x64`, `url` начинается с
  `https://github.com/WaterCa7/WaterCa7-s-pc-cleaner/releases/download/`, размер в разумных пределах (1–500 МБ),
  `sha256` — 64 hex-символа.
- `UpdateSignature` — проверка подписи открытым ключом (в тестах ключ передаётся параметром).
- `UpdateClient` — HTTP: `https://github.com/WaterCa7/WaterCa7-s-pc-cleaner/releases/latest/download/update.json`
  и `.sig` (не API GitHub — нет лимита запросов), затем exe. Только https, редиректы GitHub разрешены, таймаут
  проверки 15 с; скачивание отменяется при выходе из программы.
- `UpdateInstaller` — подготовка и установка (ниже).
- `UpdateService` — связывает всё, пишет в журнал, сообщает интерфейсу состояние.

### Проверка и скачивание

1. При запуске (не в режиме `--screenshots`, не в сборке для разработки, если включено «Обновляться автоматически»)
   в фоне скачиваются `update.json` и `update.json.sig`.
2. Нет сети, ошибка, подпись не сходится, версия не новее → ничего не показываем, пишем в журнал.
3. Новая версия → exe скачивается в `%LOCALAPPDATA%\WaterCa7sPcCleaner\Updates\<версия>\WaterCa7sPcCleaner.exe.partial`,
   сверяются размер и SHA-256 из подписанного манифеста, файл переименовывается в `.exe`, рядом кладутся
   `update.json` и `update.json.sig`.
4. Появляется полоса: «Обновление до X готово — установится при следующем запуске · Перезапустить сейчас».

### Установка (при следующем запуске или по кнопке «Перезапустить сейчас»)

В `App.OnStartup`, до создания окна:

1. Есть подготовленная версия выше текущей → заново проверить подпись `update.json` и что версия совпадает.
2. Открыть подготовленный exe с запретом записи (`FileShare.Read`) и копировать его рядом с текущим exe
   (`WaterCa7sPcCleaner.exe.new`), одновременно считая SHA-256 тех же байтов; сумма должна совпасть с манифестом.
   Так подмена файла в пользовательской папке между проверкой и установкой невозможна — важно, если программа
   запущена от администратора.
3. Переименовать текущий exe в `WaterCa7sPcCleaner.exe.old`, `.new` → `WaterCa7sPcCleaner.exe`
   (Windows разрешает переименовать запущенный exe).
4. Запустить новый exe с теми же аргументами и `--updated-from <старая версия>`, завершить текущий процесс.
5. Новая версия при запуске удаляет `.old` (несколько попыток — старый процесс может ещё завершаться) и папку
   `Updates\<версия>`, показывает полосу «Программа обновлена до X · Что нового».

Ошибки:

- Любой сбой на шагах 2–4 → вернуть `.old` на место, удалить `.new`, записать в журнал, продолжить запуск текущей
  версии. Счётчик неудач в `Updates\state.json`: после 2 неудач эта версия больше не ставится автоматически,
  полоса предлагает скачать вручную.
- Папка программы недоступна для записи (например, Program Files без прав администратора) → не ставить,
  полоса «Не удалось обновиться автоматически · Скачать вручную» со ссылкой на страницу релиза.
- Сборка для разработки (рядом с exe лежит `WaterCa7sPcCleaner.dll`, или имя exe другое) → не проверять и не ставить.

## Интерфейс

- Полоса над содержимым страницы в `MainWindow` (одна, с кнопкой действия и крестиком).
- «Настройки» → раздел «Обновления»: текущая версия, дата последней проверки, «Проверить сейчас»,
  переключатель «Обновляться автоматически» (`AppSettings.AutoUpdate`, по умолчанию `true`).
  При выключенном переключателе «Проверить сейчас» всё равно работает и предлагает установить найденное.

## Выпуск релиза (CI)

Новый workflow `.github/workflows/release.yml`, запуск по тегу `v*` на `windows-latest`:

1. Версия тега совпадает с `<Version>` в `PcCleaner.csproj`, иначе ошибка.
2. Сборка, все тесты, single-file publish (как в `ci.yml`).
3. `update.json` из размера, SHA-256, даты и текста `docs/release-notes/<версия>.md`.
4. Подпись `openssl dgst -sha256 -sign` ключом из `UPDATE_SIGNING_KEY`, проверка подписи открытым ключом из репозитория.
5. `gh release create` с тремя файлами и тем же текстом заметок.

Тег отправляется только после явного согласия пользователя.

## Открытие репозитория

1. Дождаться, пока другие сессии в этой папке закончат и всё отправят.
2. Переписать автора и коммиттера `<old-address>` → `149539786+WaterCa7@users.noreply.github.com`
   во всей истории и тегах, отправить с `--force` (`master` и `v1.0.0`), проверить, что релиз v1.0.0 цел.
3. В локальной настройке репозитория `user.email` = скрытый адрес. Пользователю — включить в GitHub
   «Keep my email addresses private» и «Block command line pushes that expose my email».
4. Добавить `LICENSE` (MIT, © 2026 WaterCa7).
5. Переключить видимость на публичную — после отдельного «да» пользователя.

## Тесты

Без сети и без изменений системы: поддельный `HttpMessageHandler`, временные папки, тестовая пара ключей.

- подписанный манифест с новой версией принимается; та же или старая версия — нет;
- неверная подпись, изменённый `update.json`, чужой `url`, неверный размер или SHA-256 — отклоняются,
  недокачанный файл удаляется;
- установка: файлы на месте, `.old` удаляется новой версией; сбой при переименовании → откат;
  подмена подготовленного файла после проверки не ставится; две неудачи → версия больше не ставится;
- сборка для разработки и режим `--screenshots` ничего не делают; выключенный переключатель не скачивает;
- открытый ключ в программе совпадает с `tools/update-signing-public.pem`.
