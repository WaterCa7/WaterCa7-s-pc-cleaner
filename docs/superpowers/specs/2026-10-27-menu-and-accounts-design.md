Дата: 2026-10-27. Статус: одобрена владельцем; дополнена в тот же день (регистрация и оплата в программе, часть S —
одобрено владельцем).
Родитель: `2026-10-23-pro-version-design.md` (этапы 2 и 4). Сервер уже работает: контракт API —
`A:\waterca7.ru\docs\api-contract-for-app.md`, спеки сайта — `A:\waterca7.ru\docs\superpowers\specs\2026-10-24-accounts-licenses-api-design.md`
и `2026-10-25-family-members-design.md`. Таблица «бесплатно / Pro» — `A:\waterca7.ru\app\data\features.php`.

## 0. Объём и разбиение

Работа «аккаунты в программе» разбита на части, у каждой своя спека и свой план:

| Часть | Что | Где | Эта спека |
|---|---|---|---|
| S | Сервер: методы API для регистрации, кода из письма, сброса пароля, цен и оплаты из программы | `A:\waterca7.ru` | да (раздел 9) |
| A | Новое меню | Windows + Mac | да |
| B | Аккаунты, лицензия, Профиль, замки Pro, обновления с waterca7.ru | Windows + Mac | да |
| C | Комплектующие полностью (SMART и износ SSD, батарея, температуры, живые показатели) | Windows (Mac — что даёт система без драйверов) | нет, своя спека |
| D | Проверка файлов (перетаскивание, «Выбрать файл», меню правой кнопки, Защитник, подпись, «из интернета») | Windows | нет, своя спека |
| E | Платный выпуск: закрытие кода, публичный репозиторий с релизами, выпуск | Windows + Mac | нет, только с «да» владельца |

Порядок: S → A → B → E (A можно параллельно с S); C и D — отдельно, параллельно или после E. Mac делается вместе с
Windows (решение владельца).

Решения владельца в этой спеке (2026-10-27):

- **Гость и бесплатный аккаунт имеют одинаковые функции** (так в утверждённой общей спеке: «без входа работает бесплатная
  часть, аккаунт нужен только для Pro»). Аккаунт даёт сервис: промокод в программе, компьютер в кабинете, обращения на
  аккаунте, Pro включается сам после покупки.
- Mac получает то же новое меню и то же деление по смыслу; разделов, которых на Mac нет, нет в меню.
- «Телефон» скрыт, пока раздел iPhone не готов (ветка `iphone-section`).
- Нынешним пользователям один раз показывается экран входа. Pro друзьям — промокодом (решение 2026-10-24).
- Вкладка, целиком закрытая Pro, показывает витрину, а не страницу.
- Общий код аккаунта пишется в Windows-репозитории и копируется в Mac (`Shared/` + `SOURCE.md`), как уже сделано с
  `HealthScoring` и др.
- **Регистрация, подтверждение почты и сброс пароля — прямо в программе**, без браузера (добавлено 2026-10-27). Браузер
  остаётся только для входа Google-аккаунтов (Google запрещает свой вход во встроенных окнах) и как запасной путь.
- **Оплата — в окне программы:** тариф и код скидки выбираются в программе, платёжная страница Robokassa открывается
  **внутри окна** (WebView2 / NativeWebView), после оплаты Pro включается сам; маленькая запасная ссылка «Оплатить в
  браузере». Своей формы ввода карты нет и быть не может: данные карты принимает только Robokassa (PCI DSS).
- Серверные методы для этого делаются в этой же работе (часть S); выкладка на Beget — только после «да» владельца.

### 1.3 Правила

- Вкладки — полоса сверху страницы раздела. Нынешние страницы (`PageViewModel`) не переписываются: раздел — новый
  `SectionViewModel` со списком вкладок-страниц. Страница с одной вкладкой показывается без полосы.
- `NavigateTo(key)` по-прежнему принимает ключ страницы (`"Disk"`, `"Network"`…): открывает раздел и вкладку. Все ссылки
  Главной и подсказки страниц работают без изменений.
- Простой режим (`UiModes`) прячет **вкладки**, а не пункты меню; раздел без видимых вкладок не показывается. Вопрос
  «переключиться на опытный режим?» для скрытой вкладки остаётся.
- Все страницы по-прежнему живут в `Pages` (проверка «страница занята» перед перезапуском, вклад в оценку Главной).
- Нижняя строка (`MainWindow.xaml`, строка 3): убрать « · Сделано для WaterCa7» и текст журнала посередине; в углу —
  `v1.5.0 · последняя версия` / `v1.5.0 · скачана 1.6.0` / `v1.5.0 · проверка…` (из `UpdateService.State`).
- `--screenshots` получает `--page Раздел/Вкладка`; без него снимает каждую вкладку отдельно.
- Новые тексты — через `T._` с английским в `en.json` (Windows); Mac пока только по-русски.

## 2. Ядро аккаунта (часть B, общий код)

Папка `src/PcCleaner/Core/Account/` в Windows-репозитории. Файлы без WPF; на Mac копируются без изменений в
`src/PcCleaner.Mac/Shared/Account/` с записью в `Shared/SOURCE.md`. Платформенное — за интерфейсами.

| Файл | Назначение |
|---|---|
| `ApiClient.cs` | `https://waterca7.ru/api/v1`, только HTTPS, JSON, `Authorization: Bearer`, `Accept-Language: ru|en`, таймауты. Ошибка → `ApiError(Code, Message, Reason, Payload)`; ветвление только по `error`. `RATE_LIMITED` → пауза и повтор не раньше, чем разрешено. Базовый адрес подменяется только в тестах |
| `ApiModels.cs` | Ответы `login`/`code`/`ticket`/`devices`/`promo`/`ticket`-обращения как записи C# |
| `LicenseKeys.cs` | Массив публичных ключей лицензий (PEM). Первый — боевой `license_pub.pem` с сервера (владелец кладёт его файлом; ключ публичный). Тестовый ключ сервера (`tests/fixtures/license_test_pub.pem`) сюда не попадает никогда — это проверяет тест по отпечатку |
| `LicenseTicket.cs` | `Verify(ticketB64, signatureB64, keys)`: base64 → байты → ECDSA P-256/SHA-256, формат **DER** (`DSASignatureFormat.Rfc3279DerSequence`) по любому ключу массива → только после этого JSON. Требует `v == 1` |
| `LicenseState.cs` | Чистая функция `Evaluate(ticket?, signedIn, hwHash, deviceId, accountId, now)` → `Tier` (`Guest`, `Free`, `Pro`) + причина (`NotSignedIn`, `NoPlan`, `Stale`, `ClockBack`, `Expired`, `WrongDevice`) + сведения для Профиля (план, `kind`, `expires_at`, дни офлайна). Pro, если подпись верна, `hw_hash`/`device_id`/`sub` свои, `plan ∈ {pro,family,custom}`, `issued_at ≤ now < valid_until` и (`expires_at` null или `now < expires_at`) |
| `Features.cs` | Ключи **как в `features.php`** (`f.home.full`, `f.clean.deep`, `f.comp.speed`…) → `free`/`pro` и признак «есть на этой платформе». `IsAvailable(key, tier)`. Неизвестный ключ — исключение в тестах |
| `AccountService.cs` | Состояние входа и событие `Changed`. Вход по паролю, вход по коду (опрос не чаще раза в 5 с, до `expires_in`, при 429 пауза растёт, при `DEVICE_LIMIT` опрос продолжается), обновление билета (при старте в фоне, раз в сутки, перед `expires_at`), выход (`/auth/logout`, локальные данные стираются), устройства, отвязка, промокод, обращение. `TOKEN_REVOKED` → данные стираются, состояние Free→«нужно войти» |
| `IAccountStore` | Токен, последний билет+подпись, `device_id`, `account_id`, `install_id`. Windows: файл в `%LOCALAPPDATA%\WaterCa7sPcCleaner\account.bin` под DPAPI (CurrentUser). Mac: Keychain |
| `IHwHash` | Windows: SHA-256 (строчный hex) от `serial платы|ProcessorId|serial системного диска` через WMI, пустое → `-`. Mac: SHA-256 от серийного номера Mac (`IOPlatformSerialNumber`) |

Имя устройства (`name`) — имя компьютера, обрезанное до 64 символов; `app_version` — три числа сборки.

## 3. Экраны (часть B)

### 3.1 Запуск

- **Первый запуск:** заставка с обновлением → экран «Войти / Зарегистрироваться / Продолжить без входа» → выбор режима и
  языка (нынешний экран приветствия) → главное окно.
- **Обновившиеся с 1.4 / Mac 1.1** (режим уже выбран, флаг `AccountIntroShown` не стоит): тот же экран входа один раз со
  строкой «Появились аккаунты и Pro», затем главное окно.
- **Дальше:** заставка → главное окно; вход запомнен. Обновление билета — в фоне, заставку не задерживает.
- `--screenshots` никогда не ходит в сеть и не показывает экран входа; уровень задаётся `--tier guest|free|pro`.

### 3.2 Окно входа

Одно окно, три вкладки; всё, кроме входа Google-аккаунтов, — без браузера.

- **«Почта и пароль»** (по умолчанию): поля, «Войти» (`POST /auth/login`), ссылка «Забыли пароль?» → шаги сброса в этом же
  окне: почта (`POST /auth/reset`) → код из письма + новый пароль дважды (`POST /auth/reset/confirm`) → вход выполнен.
- **«Регистрация»**: почта, пароль дважды, галочка «Принимаю оферту и политику конфиденциальности» (ссылки открывают
  документы во встроенном окне, раздел 3.5) → `POST /auth/register` → шаг «Введите код из письма»: 6 цифр, «Отправить ещё
  раз» с отсчётом (`POST /auth/resend`) → `POST /auth/verify` → вход выполнен (ответ как у `login`).
- **«Через браузер»** (для аккаунтов, созданных через Google, и как запасной путь): `POST /auth/code` → открыть `url` в
  браузере, показать `code` крупно и подсказку «сверьте с кодом на странице сайта»; «Открыть ещё раз», «Отмена»; ожидание
  до 10 минут.
- Требования к паролю и почте — те же, что у формы сайта (проверяются и в окне, и на сервере).
- Ответы на ошибки: `AUTH_FAILED` — «Неверная почта или пароль. Аккаунт через Google? Войдите через браузер»;
  `EMAIL_NOT_VERIFIED` (вход по паролю до подтверждения) — сразу шаг «Введите код из письма» с отправкой нового кода;
  `EMAIL_TAKEN` — «Аккаунт с этой почтой уже есть» + переход на вкладку входа; `CODE_INVALID` / `CODE_EXPIRED` — текст и
  «Отправить ещё раз»; `DEVICE_LIMIT` — «Заняты все N компьютеров» + список компьютеров аккаунта с «Отвязать» прямо в окне
  (`GET /devices` и `POST /device/unbind` с токеном, выданным для отвязки — раздел 9); нет сети — «Нет связи с
  waterca7.ru»; `RATE_LIMITED` — «Слишком много попыток, подождите N мин».

### 3.3 Профиль

- **Гость:** «Вы не вошли»; «Войти», «Зарегистрироваться» (окно входа на нужной вкладке); три строки «Что даёт Pro»;
  «Купить Pro» → окно покупки (раздел 3.5).
- **Вошёл:** почта; тариф (Free / Pro / Pro Семья / особый); срок («до 24.10.2027», «навсегда»); «проверено N назад»;
  без сети — «Pro без интернета ещё N дней»; после — «Нужна проверка лицензии через интернет». Кнопки «Купить» или
  «Продлить» (→ окно покупки), «Обновить».
- **Мои компьютеры** (`GET /devices`): имя, система, дата привязки, «этот компьютер»; у владельца семьи — чей. «Отвязать»
  (`POST /device/unbind`); при `UNBIND_QUOTA` — когда можно снова. Отвязка этого ПК = выход.
- **Промокод:** поле + «Применить» (`POST /promo/apply`); тексты на причины 1–7 (6 — «сначала войдите на этом ПК», 7 —
  «это код скидки — введите его в окне покупки»; кнопка открывает окно покупки с этим кодом).
- **Написать нам:** тема (вопрос / ошибка / другое), текст 10–5000, галочка «приложить сведения о системе и журнал»
  (журнал ≤ 1 МиБ, base64); без входа — поле почты. Ответ приходит на почту.
- **Выйти:** настройки остаются, программа переходит в бесплатный режим.

### 3.4 Замки Pro

Гость и Free видят одно и то же.

- **Вкладка целиком Pro** (Windows: Ускорение, Сеть; Mac: Сеть): замок в полосе вкладок; внутри — **витрина**: заголовок,
  3–4 пункта из таблицы сайта, «Войти» и «Купить Pro». Страница не создаёт своих проверок и не опрашивает систему.
- **Частично Pro:** Pro-проверки **не запускаются**; вместо них одна нейтральная строка «Ещё N проверок в Pro» → окно
  «Это доступно в Pro» (Войти / Купить). Кнопки Pro-действий показаны с замком и открывают то же окно.

| Ключ | Где (Windows) | Что закрыто |
|---|---|---|
| `f.home.full` | Главная | «Полная проверка» (быстрая — бесплатна) |
| `f.clean.deep`, `f.clean.dism` | Очистка | Кэш шейдеров, Discord, Steam, обновлений, отчёты, дампы; DISM |
| `f.sys.proc_deep` | Процессы | Подписи, подделки, майнеры, удалённый доступ, карантин из Процессов |
| `f.sys.startup_deep` | Автозагрузка | Задачи Планировщика, службы, «битые» записи |
| `f.sys.bloat` | Программы | Нежелательный софт, предустановленное, приложения Store |
| `f.sys.disk_deep` | Диски | Что занимает место, большие файлы, старые установщики, TRIM |
| `f.prot.deep` | Безопасность | hosts, IFEO/Winlogon, прокси, DNS, расширения браузеров |
| `f.comp.speed`, `f.prot.net` | Ускорение, Сеть | вся вкладка (витрина) |

На Mac те же ключи там, где есть аналог (глубокая очистка, подписи процессов, LaunchDaemons, нежелательные программы,
анализ места, глубокие проверки безопасности, сеть). Точное соответствие пунктов Mac — таблица в плане; ключи без аналога
помечены «нет на этой платформе».

- Правила общей спеки: **что Free нашла, то Free и исправляет**; откат (журнал, карантин, резервные копии реестра, точки
  восстановления) бесплатен всегда — восстановить из карантина можно и без Pro.
- Оценка 0–100 у Гостя и Free считается только по бесплатным проверкам.
- Pro-билет (вход, покупка, промокод, «Обновить») снимает замки **сразу**, без перезапуска; потеря Pro возвращает их на
  следующем открытии вкладки (идущая операция не прерывается).
- Простой и опытный режимы от лицензии не зависят.
- Кнопка «Войти» в витрине и окне Pro открывает окно входа; «Купить Pro» — окно покупки (гость сначала входит или
  регистрируется в нём же).

### 3.5 Окно покупки и встроенные страницы

- **Выбор:** Pro или Pro Семья (число ПК — ползунок в диапазоне с сервера), месяц / год / навсегда; цены — `GET /prices`
  (кэш на время окна; без сети — «Нет связи с waterca7.ru»). Поле «Код скидки». Итог — `POST /pay/quote` при каждом
  изменении (зачёт неиспользованного срока, скидка, «блокировано» с причиной — те же тексты, что на странице покупки
  сайта). Строка «Нажимая „Оплатить“, вы принимаете оферту и правила возврата» (ссылки — во встроенном окне).
- **«Оплатить»:** `POST /pay/start` → `{payment_id, url}`; окно переключается на встроенную страницу `url` (одноразовая
  ссылка на waterca7.ru, сразу переходит к Robokassa: карта, СБП с QR-кодом, другие способы, какие Robokassa даёт во
  встроенном виде). Кнопка «Отмена» закрывает страницу; оплата, начатая и брошенная, на сервере просто остаётся
  неоплаченной.
- **После оплаты:** переход встроенной страницы на `https://waterca7.ru/pay/app/done…` (или `…/fail`) замечается
  программой; окно показывает «Проверяем оплату…» и опрашивает `GET /pay/{id}` раз в 3 с до 2 минут (статус ставит только
  ResultURL Robokassa). `paid` → новый билет из ответа, «Pro включён до …», замки снимаются сразу. `failed` — «Оплата не
  прошла» + «Попробовать снова». Не дождались — «Оплата ещё обрабатывается; Pro включится сам» (фоновая проверка билета
  через 5 минут и при следующем запуске).
- **Запасной путь:** маленькая ссылка «Оплатить в браузере» открывает тот же `url` во внешнем браузере; дальше то же
  ожидание.
- **Встроенное окно браузера:** Windows — WebView2 (есть в Windows 10/11; если среды нет, окно предлагает браузер);
  Mac — пакет NativeWebView (WKWebView). Оно открывает только `https://waterca7.ru/…` и адреса Robokassa
  (`*.robokassa.ru`, `*.robokassa.com`) и переходы банков для 3-D Secure; прочие ссылки уходят во внешний браузер.
  Без JavaScript-мостов в программу, без сохранения карт, отдельная папка данных, которая очищается после окна.
- **Документы** (оферта, политика, правила возврата) открываются в том же встроенном окне.

- Проверка: `GET https://waterca7.ru/api/v1/update?platform=windows|mac&channel=stable&version=X.Y.Z&install_id=<UUID>&os=<≤32>`;
  200 — тело `update.json`, подпись — заголовок `X-Signature` (тот же ключ обновлений, что сейчас); 304 — актуально;
  404 `NOT_FOUND` — релизов нет (как «актуально»).
- `UpdateManifest` принимает `https://waterca7.ru/dl/{platform}/{version}/{name}` (без `v`).
- `install_id` — случайный UUID, создаётся при первой проверке. В ⚙ — выключатель «Отправлять анонимную статистику»
  (включён) и «Сбросить номер установки». Выключен — запрос без `install_id`. Проверка обновлений выключена — ни одного
  запроса и `install_id` не создаётся.
- Тексты «нет связи с GitHub» → «нет связи с сервером обновлений».
- Старые 1.4 (Windows) и 1.1 (Mac) смотрят на GitHub, поэтому выпуск части E публикуется и на сайте, и в публичный
  репозиторий релизов.

## 5. Ошибки и офлайн

- Без сети бесплатная часть работает полностью, Pro — до `valid_until` (14 дней с последней проверки).
- Часы отмотаны (`now < issued_at`) или билет устарел → Free и строка в Профиле; при появлении сети — новая попытка.
- `TOKEN_REVOKED` → выход в Free и предложение войти (один раз за запуск, не всплывающим окном поверх работы).
- Сбой сервера (5xx, таймаут, неверная подпись) не трогает бесплатную часть и не стирает действующий билет.
- Журнал пишет события входа, обновления билета и ошибки по коду; токен, пароль, билет и `hw_hash` в журнал не попадают.

## 6. Проверка

- Юнит-тесты ядра: подпись верная / чужой ключ / тестовый ключ сервера отвергнут / P1363 вместо DER / изменённый байт
  билета; чужие `hw_hash`, `device_id`, `sub`; `valid_until`, `expires_at`, отмотанные часы, `plan=free`; все коды ошибок
  API; интервал и остановка опроса кода; `TOKEN_REVOKED` стирает хранилище; DPAPI-хранилище читает только свой пользователь.
- Билеты для тестов подписываются тестовым ключом, который подставляется только в тестах.
- Тесты замков: каждый Pro-ключ закрыт у Гостя и Free и открыт у Pro; витрина не создаёт проверок; Pro-проверки не
  попадают в оценку Free.
- Тест-сверка: ключи `Features` = ключи копии `features.php` (копия в `tests/fixtures/features.php`, обновляется вручную
  при изменении таблицы на сайте).
- Меню: все прежние `NavigateTo` попадают в нужный раздел и вкладку; простой режим прячет вкладки.
- Скриншоты каждой вкладки для `--tier guest`, `free`, `pro` (Windows и Mac).
- Окно входа и покупки: шаги регистрации, кода, сброса и покупки на поддельном сервере (все коды ошибок, отсчёт
  «Отправить ещё раз», опрос `GET /pay/{id}` и его остановка); встроенная страница не открывает чужие адреса.
- Живой прогон против `https://waterca7.ru` с аккаунтом владельца: регистрация нового тестового аккаунта и код из письма,
  сброс пароля, вход по паролю и по коду, билет, устройства, промокод, отвязка, выход; покупка — в тестовом режиме
  Robokassa (`test_mode` / `test_emails` в `config.local.php`), боевой платёж делает только владелец сам, если захочет.
  Пароли, коды из писем и платёжные данные вводит владелец; в чат они не попадают.
- Mac: CI (macos-14, macos-latest, macos-15-intel) и проверка владельцем на его Mac.

## 7. Версии и выпуск

- Windows 1.5.0, Mac 1.2.0. Работа идёт в ветках (`menu-accounts` в обоих репозиториях); ничего не выпускается до части E
  и «да» владельца.
- Локальный `main` Windows-репозитория содержит коммиты спек, которые нельзя публиковать, пока репозиторий открыт;
  ветка работы делается от `origin/master`, спеки и планы переносятся в неё перед закрытием кода (часть E).

## 8. Не входит

Комплектующие сверх переноса характеристик (C), Проверка файлов (D), закрытие кода и выпуск (E), раздел Телефон,
расписание и другие будущие Pro-функции (этап 5), английский язык Mac-версии, вход через VK/Yandex/Telegram, вход Google
внутри программы (Google запрещает встроенные окна — только через браузер), своя форма ввода карты, автоплатежи,
история оплат и чеки в программе (остаются в кабинете на сайте), изменение профиля (ник, аватар) в программе.

## 9. Сервер: методы API для программы (часть S, репозиторий `A:\waterca7.ru`)

Новые методы `/api/v1` — тонкие обёртки над уже работающей логикой страниц (`Accounts`, `Codes`, `AuthPages::sendCode`,
`Prices`, `Quote`, `Discount`, `Payments`, `Provider::checkout`, `Fulfil`): страницы сайта и API вызывают одни и те же
функции, ничего не дублируется. Общие правила API (JSON, ошибки `{error, message}`, лимиты, `Accept-Language`) — как в
`api-contract-for-app.md`; этот документ дополняется новыми методами.

| Метод | Вход | Ответ и ошибки |
|---|---|---|
| `POST /auth/register` | `{email, password, consent: true, lang, hw_hash, platform, name, app_version}` | `{pending: true}`; шлёт код `verify` (как страница регистрации). `EMAIL_TAKEN` 409, `CONSENT_REQUIRED` 422, `WEAK_PASSWORD` 422, `EMAIL_INVALID` 422, `RATE_LIMITED` (5/час на IP — общий счётчик со страницей) |
| `POST /auth/verify` | `{email, code, hw_hash, platform, name, app_version}` | ответ как у `login` (токен, устройство, билет); `CODE_INVALID` 422, `CODE_EXPIRED` 410, `DEVICE_LIMIT` 409; попытки — по правилам `Codes` |
| `POST /auth/resend` | `{email, purpose: "verify"\|"reset"}` | `{ok: true, retry_after}` всегда, даже для неизвестной почты (не выдаёт, есть ли аккаунт); паузы и лимиты — как на сайте |
| `POST /auth/reset` | `{email}` | `{ok: true}` всегда; шлёт код `reset`, если аккаунт есть и у него есть пароль или только Google (тогда письмо говорит «войдите через Google или задайте пароль») |
| `POST /auth/reset/confirm` | `{email, code, password, hw_hash, platform, name, app_version}` | новый пароль, отзыв прочих сессий сайта как при сбросе на сайте, затем ответ как у `login`; `CODE_INVALID`, `CODE_EXPIRED`, `WEAK_PASSWORD`, `DEVICE_LIMIT` |
| `GET /prices` | — | `{currency:"RUB", plans:[{plan, term, devices?, price}], family:{min,max,default}, payments_enabled}` — те же цифры, что на `/pricing` |
| `POST /pay/quote` | Bearer, `{plan, term, devices, promo?}` | `{list, discount, credit, amount, action, term, expires_at?}` или ошибка как на странице покупки (`PROMO_INVALID` с `reason`, `BLOCKED` с причиной, `EMAIL_NOT_VERIFIED`, `PAYMENTS_DISABLED`) |
| `POST /pay/start` | Bearer, то же | `{payment_id, url}`; `url` = `https://waterca7.ru/pay/app/{id}?t=<одноразовый токен, 15 мин>`; лимит оплат в час — как на странице (`PAY_MANY`) |
| `GET /pay/app/{id}?t=…` | (страница) | проверяет и гасит токен, отдаёт ту же автоформу перехода на Robokassa, что `/account/buy`, но с `SuccessURL`/`FailURL` = `/pay/app/done`, `/pay/app/fail` (простые страницы «Можно вернуться в программу»; без сессии и кабинета) |
| `GET /pay/{id}` | Bearer, только своя оплата | `{status: "pending"\|"paid"\|"failed"}`, при `paid` ещё `{ticket, signature}` |

- `DEVICE_LIMIT` у `login`, `verify`, `reset/confirm` и опроса кода дополнительно отдаёт `unbind_token` (живёт 10 минут,
  годится только для `GET /devices` и `POST /device/unbind` этого аккаунта; правило «не чаще раза в 7 дней» действует).
  После отвязки программа повторяет вход тем же способом.
- Для оплат из программы в `payments` отмечается источник (`source = 'app'`), чтобы в админке было видно, откуда покупки.
- Тесты PHP на каждый метод (успех, каждая ошибка, лимиты, чужая оплата, повторное использование токена `/pay/app`),
  расширение `api-smoke`; `docs/api-contract-for-app.md` дополняется.
- Миграция БД (если нужны поля `source`, токен `/pay/app`, `unbind_token`) — отдельным файлом `db/migrations/0NN_app_api.sql`.
- Выкладка на Beget — по чеклисту выкладки сайта, только после «да» владельца; до неё программа проверяется на локальном
  сервере сайта (`scripts/serve.ps1`) с тестовым ключом лицензий.
